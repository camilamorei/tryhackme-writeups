# Network Security Essentials

## Overview

This room introduces network security from a defensive perspective, focusing on network components, network visibility, perimeter protection, firewall logs, and incident investigation.

The exercises cover port scanning, web application attacks, VPN brute-force attempts, lateral movement, command and control (C2) beaconing, and potential data exfiltration.

## Task 3: A Network Overview

An enterprise network consists of interconnected devices and services that support communication and resource sharing.

Important network components include:

- User workstations and other endpoints.
- File and database servers.
- Application servers, including web, email, and VPN services.
- Active Directory and authentication servers.
- Routers and switches.
- Firewalls and other perimeter security devices.

Each component has a different security role. Endpoints can be compromised through phishing or malicious downloads, while servers and identity systems are valuable targets for attackers.

Firewalls control network traffic according to security rules and provide logs that can reveal scanning, unauthorized access attempts, and suspicious connections.

## Task 4: Network Visibility

Network visibility is the ability to monitor and understand activity across a network. It helps security analysts detect anomalies, investigate incidents, hunt for threats, and identify potential data exfiltration.

There are two main categories of logs.

### Host-Centric Logs

Host-centric logs are generated by individual systems. Examples include Windows Event Logs, Linux syslog, application logs, antivirus logs, and Endpoint Detection and Response (EDR) events.

These logs help analysts investigate process execution, file modifications, user logins, and the direct impact of an attack on a host.

### Network-Centric Logs

Network-centric logs are generated by network devices and security appliances. Examples include:

- Firewall logs.
- IDS/IPS alerts.
- Router and switch flow data.
- Web proxy logs.
- VPN authentication logs.

These logs reveal source and destination addresses, ports, protocols, connection outcomes, and suspicious traffic patterns.

Correlating host-centric and network-centric logs helps analysts reconstruct an attack timeline and identify the systems involved.

## Task 5: Network Perimeter

The network perimeter separates an organization's trusted internal network from untrusted external networks.

Common perimeter components include:

- Firewalls that inspect and filter network traffic.
- Routers and gateways that direct traffic between networks.
- A Demilitarized Zone (DMZ) that isolates public-facing services.
- VPN gateways that provide remote access.

Perimeter monitoring helps identify exposed services, port scans, brute-force attacks, exploitation attempts, unauthorized access, and suspicious outbound traffic.

## Task 7: Perimeter Logs: Investigating the Breach

This task investigates firewall, IDS, and VPN logs to determine how an attacker gained access, moved through the internal network, communicated with external infrastructure, and attempted data exfiltration.

### Log Analysis with Linux Commands

The following commands demonstrate how to investigate the logs manually.

Identify blocked firewall connections:

```bash
grep "BLOCK" firewall.log | head
```

Count blocked requests by source IP:

```bash
grep "BLOCK" firewall.log | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -nr
```

Identify the internal hosts receiving the most blocked connections:

```bash
grep "BLOCK" firewall.log | awk '{print $7}' | cut -d: -f1 | sort | uniq -c | sort -nr
```

Identify failed VPN authentication attempts:

```bash
grep "FAIL" vpn_auth.log
```

Find authentication activity associated with the targeted service account:

```bash
grep "svc_backup" vpn_auth.log
```

Inspect IDS alerts related to SMB lateral movement:

```bash
grep "MS-SMB Lateral Movement" ids_alerts.log
```

Search for possible command and control beaconing:

```bash
grep "C2 Beaconing" ids_alerts.log
```

Search for potential data exfiltration alerts:

```bash
grep "Potential Data Exfiltration" ids_alerts.log
```

### Investigation Findings

Answers:

- External IP that performed the most reconnaissance: `203.0.113.45`
- Internal host targeted by scans: `10.0.0.20`
- Username targeted in VPN logs: `svc_backup`
- Internal IP assigned after successful VPN login: `10.8.0.23`
- Port used for lateral SMB attempts: `445`
- Internal host that beaconed to the C2 server: `10.0.0.60`
- IP address associated with the C2 server: `198.51.100.77`
- Host that showed data exfiltration attempts: `10.0.0.51`

### Log Analysis with Splunk

The room also provides a Splunk instance with the logs stored in the `network_logs` index.

Example queries:

Find blocked firewall events grouped by source IP:

```spl
index="network_logs" sourcetype="firewall_logs" action="BLOCK"
| stats count by src_ip
| sort -count
```

Identify internal destinations targeted by blocked connections:

```spl
index="network_logs" sourcetype="firewall_logs" action="BLOCK"
| stats count by dst_ip
| sort -count
```

Identify targeted VPN usernames:

```spl
index="network_logs" sourcetype="vpn_logs"
| stats count by username
| sort -count
```

Investigate possible C2 beaconing:

```spl
index="network_logs" sourcetype="ids_logs" alert="ET TROJAN Possible C2 Beaconing"
```

Identify sources associated with potential data exfiltration:

```spl
index="network_logs" sourcetype="ids_logs" classification="Potential Data Exfiltration"
| stats count by src_ip
| sort -count
```

### Attack Timeline and Interpretation

The investigation demonstrates a possible attack progression:

1. Reconnaissance through repeated connections to multiple ports.
2. Credential attacks against the VPN service account.
3. Successful VPN authentication and assignment of an internal address.
4. Lateral movement attempts using services such as SSH, SMB, and RDP.
5. Periodic communication with an external C2 server.
6. Potential data exfiltration through large HTTP POST uploads.

The findings should be correlated across firewall, VPN, and IDS logs to confirm the sequence of events and identify the affected systems.

## Task 8: Conclusion

This room covers essential defensive network security concepts, including network architecture, visibility, perimeter protection, and log analysis.

The practical investigation demonstrates how security analysts can identify reconnaissance, brute-force attempts, lateral movement, C2 communication, and potential data exfiltration by correlating multiple log sources.

## Key Takeaways

- Network visibility depends on collecting and correlating useful logs.
- Firewalls provide visibility into allowed and blocked connections.
- WAF and IDS alerts can help identify suspicious requests and potential exploits.
- VPN logs can reveal repeated authentication failures and compromised accounts.
- SMB traffic on port 445 can be associated with lateral movement.
- Repeated or periodic connections may indicate C2 beaconing.
- Large outbound data transfers can indicate potential exfiltration.
