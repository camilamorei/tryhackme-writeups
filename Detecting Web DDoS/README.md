# Detecting Web DDoS

## Overview

This room explores Denial-of-Service (DoS) and Distributed Denial-of-Service (DDoS) attacks, their motivations, detection methods, and defensive techniques. It also introduces web server log analysis and SIEM platforms through a hands-on Splunk investigation.

## Learning Objectives

- Understand the difference between DoS and DDoS attacks.
- Identify common motivations behind DDoS attacks.
- Analyze web server logs to detect suspicious traffic.
- Use Splunk to investigate potential DDoS activity.
- Identify indicators such as repeated requests, suspicious IP addresses, user agents, and HTTP status codes.
- Understand how CDNs, load balancing, and Web Application Firewalls help mitigate attacks.

## 1. Denial-of-Service Attacks

A Denial-of-Service attack attempts to make a service unavailable to legitimate users by overwhelming its resources or disrupting its operation.

A Distributed Denial-of-Service attack uses multiple compromised devices to generate traffic against a target simultaneously.

### DoS vs. DDoS

| DoS | DDoS |
|---|---|
| Usually originates from a single source. | Originates from multiple sources. |
| Traffic is generated by one system or connection. | Traffic is distributed across many systems. |
| May be easier to trace to its source. | Attribution is more difficult because of distributed traffic. |

A botnet is a network of compromised devices that can be controlled to generate malicious traffic during a DDoS attack.

## 2. Attack Motivations

DDoS attacks can be motivated by several factors:

- Hacktivism: Disrupting services to promote a political or social cause.
- Reputational damage: Reducing customer confidence in an organization.
- Financial motivations: Extortion or disruption of a competitor.
- Service disruption: Making websites or applications unavailable to legitimate users.

Understanding the attacker's motivation can help security analysts investigate incidents and assess their potential impact.

## 3. Web Server Log Analysis

Web server logs provide information about incoming requests and can help analysts identify suspicious activity.

Important indicators include:

- Source IP addresses generating unusually high request volumes.
- Repeated requests to the same URI or endpoint.
- Suspicious or repetitive user agent strings.
- Sudden increases in traffic over a short period.
- HTTP 503 Service Unavailable responses, which may indicate that a server is unable to handle requests.

A single indicator does not necessarily confirm a DDoS attack. Analysts should correlate multiple indicators and compare traffic against normal activity.

## 4. SIEM Investigation with Splunk

Security Information and Event Management (SIEM) platforms collect and analyze logs from different sources. They help analysts search large datasets, identify patterns, and investigate potential security incidents.

Splunk was used to investigate a simulated DDoS attack and identify traffic patterns.

### Useful Splunk Queries

Find the most frequently requested URIs:

```spl
index="main" | top uri
```

Count requests grouped by URI and client IP:

```spl
index="main" | stats count by uri clientip
```

Count distinct client IP addresses within a suspected botnet range:

```spl
index="main" clientip="203.0.113.*" | stats dc(clientip)
```

Identify the most common user agents:

```spl
index="main" | top useragent
```

Visualize request volume over time:

```spl
index="main" | timechart span=1s count
```

Investigate HTTP 503 responses received by internal clients:

```spl
index="main" status=503 clientip="10.*" | sort 0 _time
```

These searches help identify high request volumes, repeated endpoints, distributed sources, common user agents, traffic spikes, and service errors.

### Investigation Findings

The Splunk exercise identified the following indicators:

- Most frequently requested URI: `/search`
- Client IP generating the most requests to the target URI: `203.0.113.7`
- Number of distinct IP addresses in the simulated botnet: `60`
- Most common attacking user agent: `Java/1.8.0_181`
- Peak request rate: `207 requests per second`
- First legitimate client identified receiving an HTTP 503 response after the attack: `10.10.0.27`

These findings illustrate how SIEM queries can help establish the scope and timing of a suspected DDoS incident.

## 5. DDoS Mitigation

Organizations use multiple defensive controls to reduce the impact of DDoS attacks.

### Content Delivery Networks

A Content Delivery Network (CDN) distributes content across geographically distributed servers. This can reduce the load on the origin server and help absorb or mitigate certain traffic floods.

### Load Balancing

Load balancing distributes incoming requests across multiple servers. This helps prevent a single server from becoming a bottleneck, although it does not eliminate every type of DDoS attack.

### Web Application Firewalls

A Web Application Firewall (WAF) filters HTTP and HTTPS traffic according to security rules. It can help block malicious web requests and protect applications from certain application-layer attacks.

### CAPTCHA

CAPTCHA challenges help distinguish many automated requests from human interactions. They can reduce some forms of bot activity but are not a complete defense against DDoS attacks.

Effective mitigation generally requires layered defenses, traffic monitoring, rate limiting, and coordination with hosting providers or DDoS protection services.

## 6. Key Takeaways

- DoS and DDoS attacks target service availability.
- DDoS attacks commonly use botnets to generate distributed traffic.
- Web server logs can reveal suspicious IP addresses, repeated URIs, abnormal request rates, and HTTP errors.
- SIEM platforms such as Splunk help analysts investigate large volumes of security data.
- CDNs, load balancing, WAFs, and other layered controls help reduce the impact of attacks.
- Reliable detection requires correlating multiple indicators rather than relying on a single event.
