# Walking An Application

## Overview

This room focuses on manually reviewing web applications using browser developer tools. It covers how to identify potential security issues by inspecting HTML, CSS, JavaScript, network requests, and locally stored data.

## Learning Objectives

- View and analyze website source code.
- Inspect and modify HTML elements.
- Understand JavaScript execution and debugging.
- Analyze HTTP requests using the Network panel.
- Identify cookies and locally stored data.

## Task 1 - Walking An Application

Deployed the AttackBox and Lab Machine, then accessed the Acme IT Support website using Firefox.

## Task 2 - Exploring The Website

Explored the website and identified its main pages and interactive features.

Important endpoints discovered:

- `/news`
- `/news/article?id=1`
- `/contact`
- `/customers/login`
- `/customers/signup`
- `/customers/reset`
- `/customers/ticket/new`
- `/customers/account`
- `/customers/logout`

The endpoint for creating new support tickets is `/customers/ticket/new`.

## Task 3 - Viewing The Page Source

Inspected the HTML source code to identify information exposed by the application.

Key findings:

- HTML comments can expose sensitive information or developer notes.
- Hidden links may reveal undocumented application endpoints.
- Directory listing can expose files that should not be publicly accessible.
- Framework identification can reveal outdated software versions and potential vulnerabilities.

## Task 4 - Developer Tools: Inspector

Used the browser Inspector to examine the live DOM and CSS styles.

Identified the `premium-customer-blocker` element and modified its CSS `display` property from `block` to `none`.

This revealed content hidden behind the paywall.

This demonstrates how client-side restrictions can be bypassed when access control is implemented only in the browser.

## Task 5 - Developer Tools: Debugger

Inspected the `flash.min.js` JavaScript file on the Contact page.

Used Pretty Print to improve code readability and located the `flash['remove']();` instruction.

Created a breakpoint to pause JavaScript execution before the red notification was removed.

This demonstrated how breakpoints can help analyze JavaScript behavior and reveal hidden information.

## Task 6 - Developer Tools: Network

Used the Network panel to monitor HTTP requests generated by the Contact form.

Submitted a message and identified the AJAX request sent to the `contact-msg` endpoint.

Inspected the request and its Response tab to retrieve information returned by the server.

## Task 7 - Developer Tools: Storage

Inspected browser storage and cookies after logging into the customer area.

Identified the HttpOnly cookie attribute and confirmed its value was `false`.

HttpOnly is a cookie security attribute that prevents JavaScript from accessing a cookie when enabled.

When disabled, cookies may be accessible through JavaScript, increasing the potential impact of Cross-Site Scripting (XSS) vulnerabilities.

## Task 8 - Conclusion

Completed the room and learned how to manually assess web applications using built-in browser tools.

Key concepts covered:

- HTML source code inspection
- Hidden endpoints and directory listing
- DOM manipulation
- Client-side access restrictions
- JavaScript debugging and breakpoints
- HTTP requests and AJAX
- Cookies and browser storage
